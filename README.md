# 美好生活资产现金管理 | Better Life Asset Management

一个采用**摩根士丹利专业金融风格**设计的Web应用，用于管理和分析结构化金融产品的现金流。支持整装/局装资产分类管理、信托端过手摊还和固定摊还两种模式的现金流计算、压力测试分析。

## 📊 数据流架构 (v3.21.5)

### 多信托模型数据隔离

```
┌─────────────────────────────────────────────────────────────────┐
│                     用户界面 (UI Layer)                          │
├─────────────┬─────────────┬──────────────┬──────────┬───────────┤
│   仪表盘    │  资产管理   │ 资产端现金流 │ 信托端   │ 压力测试  │
│ Dashboard   │   Assets    │  Cashflow    │ Trust    │  Stress   │
├─────────────┴─────────────┴──────────────┴──────────┴───────────┤
│                     AppState (内存状态)                          │
│    AppState.assets = [...] ← 当前模型的资产数据                  │
├─────────────────────────────────────────────────────────────────┤
│                     API Layer (数据访问层)                       │
│    getAllAssets() → 自动按 ModelManager.currentModelId 过滤      │
│    createAsset()  → 自动添加 modelId 字段                        │
├─────────────────────────────────────────────────────────────────┤
│                   数据库 (RESTful Table API)                     │
│    表: structured_finance_assets                                 │
│    记录: { asset_id, asset_type, ..., modelId: 'model_xxx' }     │
└─────────────────────────────────────────────────────────────────┘
```

### 各模块数据源（统一指向当前模型）

| 模块 | 触发时机 | 数据获取方式 | 数据来源 |
|------|----------|--------------|----------|
| **仪表盘** | 页面加载/切换模型 | `API.getAllAssets()` | 当前模型数据库 |
| **资产管理** | 切换到资产管理标签 | `API.getAssets()` | 当前模型数据库 |
| **资产端现金流** | 点击"运行分析" | `API.getAllAssets()` | 当前模型数据库 |
| **信托端分析** | 切换标签/点击"运行分析" | `API.getAllAssets()` | 当前模型数据库 |
| **压力测试** | 切换标签/点击"运行测试" | `API.getAllAssets()` | 当前模型数据库 |
| **数据导入** | 确认导入 | `API.createAssetsBatch()` | 写入当前模型 |

### 数据同步机制

1. **导入后即时刷新**：导入完成后直接使用已导入数据更新所有UI，无需重新从API加载
2. **切换模型时**：自动保存当前模型数据，加载目标模型数据
3. **侧边栏资产数量**：当前展开的模型显示实时数据，其他模型显示缓存数据

## 💰 信托现金流计算逻辑

### 过手摊还模式 - 季度 (Pass-Through Quarterly)
- 每季度资产端回款**全部用于偿还**
- 偿还顺序（🆕 v3.11.0调整）：
  1. **前置中介费用**（仅第一季度）
  2. **税金**（季度回款 × 应税比例 × 有效税率）
  3. 优先级利息
  4. 劣后级利息
  5. 优先级本金
  6. 劣后级本金
  7. 超额收益
- **最后一期释放信保基金**

### 过手摊还模式 - 月度 (Pass-Through Monthly) 🆕 v3.46.1
- 每月资产端回款**全部用于偿还**（更频繁的分配）
- 偿还顺序（与季度完全一致）：
  1. **前置中介费用**（仅第一月）
  2. **税金**（当月回款 × 应税比例 × 有效税率）
  3. 优先级利息（月度利率 = 年化利率/12）
  4. 劣后级利息
  5. 优先级本金
  6. 劣后级本金
  7. 超额收益
- **最后一期释放信保基金**
- **与季度模式的差异**：
  - 每月即偿本金 → 本金余额下降更快 → 利息计提基础更小 → **优先级利息更少**
  - 无季度暂存利息（月度即付，资金不在账上停留）
  - 信保基金利息按月计提

### 固定摊还模式 (Fixed Amortization) - 🆕 v3.12.0增强
- **🆕 优先级预计还款期限参数**（信托端分析配置区始终可见）：
  - 1年（4个季度）
  - 1.5年（6个季度）
  - 2年（8个季度）- 默认
  - 2.5年（10个季度）
  - 3年（12个季度）
- **两种还款方式**：
  - **等额本息**：每季度还款金额固定，利息递减本金递增
  - **等额本金**：每季度还本金固定，还款金额递减，总利息更少
- 偿还顺序（🆕 v3.11.0调整）：
  1. **前置中介费用**（仅第一季度）
  2. **税金**（季度回款 × 应税比例 × 有效税率）
  3. 优先级利息
  4. 劣后级利息
  5. 优先级本金（按选定期限和方式计算）
- 偿还完优先级本金后，剩余资金保留在信托池累计
- **分年度统计累计沉淀**
- **🆕 结果显示还款配置**：还款期限、还款方式、季度还款、首季还款
- **🆕 月度还款市场分析**：预计还清期限、两种还款方式对比、利息节省分析

### v3.45.54 (2026-01-28) - 修复临界PD计算逻辑

**🔧 修复PD（违约概率）计算导致临界PD偏高10倍的问题**：

| 问题 | 原因 | 修复 |
|------|------|------|
| 临界PD显示~10%，预期应为~3% | 月度PD计算错误：月度PD = 年化PD/12，导致累计违约 = 总回款 × 年化PD × 5 | 直接使用年化PD作为违约损失率，累计违约 = 总回款 × 年化PD |

**PD定义修正**：
- **年化PD = 3%** 的正确含义：一年内约3%的回款会因违约而损失
- **累计违约损失** = 总回款 × 年化PD（而不是 × 年化PD × 年数）

**之前的错误计算**：
```
月度PD = 年化PD / 12
每月违约 = 当月回款 × 月度PD
累计违约 = 总回款 × (年化PD/12) × 60月 = 总回款 × 年化PD × 5  // 太高了！
```

**修正后的计算**：
```
每期违约 = 当期回款 × 年化PD
累计违约 = 总回款 × 年化PD  // 符合预期
```

**影响**：
- 临界PD将从~10%下降到~3%左右（与超额收益率相近）
- 压力测试的违约损失金额将大幅减少
- 更准确地反映实际信用风险

| 现象 | 原因 | 说明 |
|------|------|------|
| 信托期内资产回款 > 原始回款 | 累积效应 | 之前被空置期推迟的回款在信托期内累积到账 |
| 信托期内资产回款 < 原始回款 | 推迟效应 | 信托期内的回款被空置期推迟到信托期后 |
| 全周期资产回款 = 全周期原始回款 | 守恒 | 空置期只推迟时间，不减少总金额 |

|------|------|------|----------|
| 原始回款 | 紫色 | 信托期内理论应还款（不含空置期） | `calculateDetailedCashflow()` |
| 资产回款 | 蓝色 | 信托期内实际到账（含空置期调整） | `calculateCashflowWithVacancy()` |
| 空置期累积/推迟 | 青/橙 | 资产回款 - 原始回款 | 正数=累积，负数=推迟 |

| 60期后回款 | 橙色 | 全周期原始 - 信托期内原始 | 资产期限 > 信托期限时产生 |

### v3.45.27 (2026-01-25)

#### 🔧 固定摊还累积沉淀计算修复

**问题描述**：
在固定摊还模式下，当劣后级本金偿还完毕后，后续各期的净回款（档期沉淀）不会累加到累积沉淀中，导致最后几期的累积沉淀数字错误。

**根本原因**：
在 `calculateFixedAmortizationCashflow` 函数中，当劣后级还清时（subordinateBalance <= 0.01），代码将 `cashReserve` 直接设为0，而不是继续累加后续期次的超额收益。

**修复方案**：
```javascript
// 修复前 (错误)
if (subordinateBalance > 0.01) {
    // 劣后级未还清...
} else {
    // 劣后级已还清：剩余资金为超额收益
    excessReturn = Math.max(0, availableForPayment);
    totalExcess += excessReturn;
    cashReserve = 0;              // ❌ 错误：直接清零
    periodReserveIncrease = 0;    // ❌ 错误：不记录
}

// 修复后 (v3.45.27)
if (subordinateBalance > 0.01) {
    // 劣后级未还清...
} else {
    // 劣后级已还清：剩余资金继续累积为超额收益/沉淀
    excessReturn = Math.max(0, availableForPayment);
    totalExcess += excessReturn;
    periodReserveIncrease = excessReturn;  // ✅ 记录当期沉淀
    cashReserve = prevCumulativeReserve - usedReserve + excessReturn;  // ✅ 累加
    cashReserve = Math.max(0, cashReserve);
}
```

### v3.45.13 (2026-01-23)

#### 🔧 现金流勾稽问题修复

**问题描述**：
- 资产总代扣金额9060万，已代扣600万，理论剩余8400万
- 但资产端现金流只计算出7400万，差异1000万

**根本原因**：
在 `runFullAnalysis`（仪表盘全部分析）中，分析起始日固定为"今天"，分析周期固定为60个月。如果资产的剩余期数起始日（起租日+已代扣期数）早于今天，那些"已经过去但尚未代扣"的期数会被跳过。

**修复方案**：

```javascript
// 修复前
const cashflowStartDate = new Date();  // 固定为今天
const cashflowMonths = 60;              // 固定60个月

// 修复后 (v3.45.13)
let cashflowStartDate = new Date();
let cashflowMonths = 60;

// 1. 计算最早的剩余期起始日
const earliestRemainingDate = calculateEarliestRemainingDate(assets);
if (earliestRemainingDate < cashflowStartDate) {
    // 将分析起始日前移到最早剩余期日
    const extraMonths = monthDiff(earliestRemainingDate, cashflowStartDate);
    cashflowMonths += extraMonths;
    cashflowStartDate = earliestRemainingDate;
}

// 2. 确保覆盖所有资产的完整生命周期
const fullLifecycleMonths = calculateFullLifecycleMonths(assets, cashflowStartDate);
if (fullLifecycleMonths > cashflowMonths) {
    cashflowMonths = fullLifecycleMonths;
}
```

**修复范围**：
1. `runFullAnalysis` - 仪表盘"运行全部分析"
2. `runTrustAnalysis` - 信托端分析
3. `runCashflowAnalysis` - 资产端现金流分析

**信托端原始回款修复**：
- 过手摊还和固定摊还现金流明细中的"原始回款"列
- 现在与资产端现金流使用相同的起始日和分析周期
- 确保三处计算结果完全一致

### v3.41.1 (2026-01-15)

#### 🔧 整装资产去化期与PD风险逻辑修正

**核心修正**：
1. **PD不是年化概念**：每次购买整装资产在去化周期内都有PD违约概率
2. **去化期内剩余期数不变**：因为没有转为可转让状态，没有租金回款，`remainingPeriods`不递减
3. **正确的时间线**：去化完成后再经过持有期才出售

**去化+出售时间线**：
```
资产购入 → 去化期（约1个月）→ 持有期（1个月）→ 出售

具体示例（假设持有期=1个月）：
- 第1周去化30%的资产 → 持有1个月 → 第5周出售
- 第2周去化30%的资产 → 持有1个月 → 第6周出售  
- 第3周去化20%的资产 → 持有1个月 → 第7周出售
- 第4周去化20%的资产 → 持有1个月 → 第8周出售
```

**去化期内的状态**：
```
┌─────────────────────────────────────────────────────────────┐
│ 去化期内（约1个月）：                                        │
│ - 资产状态：待去化（isTransferable = false）                 │
│ - 租金回款：无（资产尚未转让给租户）                         │
│ - remainingPeriods：不变（不产生回款消耗）                   │
│ - PD风险：存在（每次购买都有PD违约概率）                     │
├─────────────────────────────────────────────────────────────┤
│ 可转让状态后：                                               │
│ - 资产状态：可转让（isTransferable = true）                  │
│ - 租金回款：产生（资产已转让给租户）                         │
│ - remainingPeriods：递减（每月收到租金回款）                 │
│ - holdPeriods：递增（计算持有期）                            │
│ - 出售条件：holdPeriods >= holdTarget 或 最后一期            │
└─────────────────────────────────────────────────────────────┘
```

**风险参数说明**（v3.41.1修正）：

```
整装PD：0.2%（每次去化周期内的违约概率，非年化）

风险损失 = 违约资产购入成本 × LGD
```

**代码变更**：


**2. 中长期资产（整装）- 流转策略**
```

- 购买价格 = 面值 × 86%（86折）
- 持有期限 = 1期（可配置）
- 到期卖出价格 = 剩余原值 × 88%

收益计算：
- 持有期间回款 = 原值 / 总期数（每月代扣，归信托）
- 卖出差价 = 卖出价(88%) - 对应成本(86%) ≈ 2.33%
- 最后一期强制卖出所有中长期资产，确保全部变现
```

**3. 循环购买策略**
```

- 最后shortPeriod期（默认10期）：停止购买短期，全部买中长期
- 最后holdPeriod期（默认1期）：停止购买中长期
```


**2. 中长期资产循环收益计算修正**

核心公式：**86折买入，88折卖出 = 2.33%循环收益**

```javascript
// 循环收益率 = 卖出折扣 / 买入折扣 - 1
circulationYieldRate = 88% / 86% - 1 ≈ 2.33%

// 每次卖出的循环收益
sellPrice = 剩余原值 × 88%（卖出折扣）
correspondingCost = 剩余原值 × 86%（买入折扣）
circulationProfit = sellPrice - correspondingCost
```

```
短期资产持有策略：

└── 持有收益 = 回款 - 购入成本 = 原值 × 5%
```

**分层折扣率规则**：
| 资产剩余期限 | 购入折扣率 | 策略选择 |
|-------------|-----------|---------|

| 12-36期（1-3年） | **86折** | 仅流转型策略 |
| > 36期（3年以上） | **83折** | 仅流转型策略 |

**两种策略说明**：
1. **持有型策略**
   - 持有至资产到期，获取全部代扣收益

   - 出售前的代扣收入归属放款池信托
   - 收益 = 持有期间代扣收入 + 出售收入 - 购入成本

**短期资产策略选择**（<12期）：
- **自动对比推荐**：系统计算两种策略收益，推荐收益更高的策略
- **手动选择**：可在配置中强制选择持有型或流转型策略

**新增UI组件**：
1. **流转型专用配置区域**（仅流转型信托显示）
   - 分层折扣率设置（短期95%、中期86%、长期83%）
   - 流转出售折扣率（88%）
   - 短期资产策略选择下拉框

2. **流转型策略分析面板**（分析结果中显示）
   - 资产分层统计（短/中/长期资产数量和金额）
   - 短期资产双策略对比（持有型 vs 流转型）
   - 策略推荐提示
   - 综合收益汇总

**计算示例**：
假设有一笔短期资产，剩余期限6期，待代扣余额100万

- 流转型：购入95万，立即以88万出售，净收益-7万
